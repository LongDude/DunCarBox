# DunCarBox — frontend foundation

## Что уже работает

React + TypeScript + Vite. `src/pages/FoundationPage.tsx` объединяет небольшие компоненты,
`src/features/demo/` управляет выбором сценария и показывает результат, `src/api/` содержит
единый fetch-клиент и асинхронные состояния. Полный контракт находится в
`src/types/packing.ts`, источник истины — [CONTRACTS.md](CONTRACTS.md).

Пользователь видит статус подключения к API, выбирает один из четырёх серверных сценариев,
просматривает товары/доступные коробки и запрашивает демо-план. Результат показывает
success/partial/impossible, метрики, причины проблем, неуложенные единицы и инструкции.
Инструкции показываются из ответа API и не генерируются повторно на клиенте.
Foundation явно помечен «Демонстрационный режим»: backend возвращает подготовленные
fixtures; произвольные заказы пока не поддерживаются. Это не готовый упаковочный алгоритм.

Загрузка, ошибка сети/API, таймаут 15 секунд, повторная попытка и пустой результат
обрабатываются отдельно. При смене сценария старый расчёт прерывается, его результат
сбрасывается; запоздалые ответы не перезаписывают текущий сценарий. Во время POST кнопка
отключена. Смена сценария остаётся доступной. Работают клавиатурный фокус, подписи состояний
для screen reader, responsive layout и reduced-motion.

В разработке Vite слушает порт 5173 и проксирует `/api` на `127.0.0.1:8000`.
В Docker frontend доступен через nginx на порту 8080; браузер использует относительный
`/api/v1`, адрес backend не зашивается в bundle. `npm run build` включает строгую проверку
TypeScript. Three.js и React Three Fiber установлены для следующего этапа, но пока не
загружаются в страницу.

## Координаты для 3D

В домене все размеры и позиции — целые миллиметры; вес — граммы. x направлен вправо
(length), y вглубь (width), z вверх (height). Начало — передний левый нижний внутренний угол.
`Placement.position` — минимальный угол, `dimensions` — уже ориентированные размеры.

Для Three.js с Y вверх точка `(x, y, z)` отображается в `(x, z, -y)`.
Центр mesh: `(x + length/2, z + height/2, -(y + width/2))`.
Размеры BoxGeometry: `(length, height, width)`. Повторно применять `orientation` к размерам
нельзя. Общий масштаб камеры/сцены допустим только на границе рендера; API-данные не менять.

## Шаги упаковки

Для каждой коробки API возвращает `instructions`:

- `step=0`, `prepare_box`: взять коробку; сцена показывает пустую коробку.
- `step=1..N`, `place_item`: текст и ссылки точно соответствуют `Placement`.
- `step=N+1`, `close_box`: закрыть коробку; сцена показывает все размещённые товары.

На шаге k показывать товары со `placement.step < k` как уже уложенные, `step = k` как текущий,
`step > k` скрывать. При смене коробки начинать с её `prepare_box`. Подписи показывать
по-русски, в том числе ориентацию и положение из серверного текста. В foundation список
нумеруется для человека с 1, но в API идентификаторы шагов остаются 0..N+1.

Выбор единиц для отображения не меняет контракт: например, UI может показывать массу в кг
через деление на 1000, сохраняя вычисления и запросы в граммах. `fill_ratio` — доля 0..1,
в UI умножается на 100. Показанный вес — только упакованные товары, без массы коробок.
