# Алгоритм 2: Z3

`Z3PackingEngine` использует целочисленную геометрию, независимую проверку
размещений и эвристический начальный план с полной опорой.

## Повороты и цель

Поворот вокруг вертикальной оси разрешён всегда: `LWH` и `WLH`, с удалением
геометрических дублей. `allow_rotation=false` запрещает смену основания:
исходная высота сохраняется. При true разрешены все шесть перестановок осей.

Оба алгоритма сравнивают планы в таком порядке:

1. Максимум **общего заполнения**: U/V, где U — объём упакованных товаров,
   V — суммарный объём использованных коробок.
2. При одинаковом заполнении — максимум количества упакованных единиц.
3. Затем максимум объёма упакованных товаров.
4. Затем минимум количества коробок.

Используются точные рациональные числа, а не округлённый `fill_ratio`.
Пустой план имеет заполнение 0. Частичный план может быть лучше полного.
Для эвристики далее учитываются удобство укладки, остатки и каноническая геометрия.

Общий процент является средним процентов коробок с весами, равными их объёмам.
Поэтому добавление коробки с меньшим заполнением снижает основную цель.
Эвристика оставляет в каждом найденном плане все коробки с максимальным
заполнением, возвращая остальные товары в `unpacked_items`.
При недостаточном поиске эвристический результат не гарантирует оптимума.

## Точная оптимизация отношения

Прямое деление двух переменных заменено последовательностью линейных задач
(метод Динкельбаха). Для текущего достигнутого заполнения r=p/q решается:

```text
maximize gain = q*U - p*V
then maximize packed_count
then maximize U
then minimize box_count
```

Положительный gain означает строго более высокое заполнение: текущая дробь
обновляется, ограничения сохраняются, цели перестраиваются.
Доказанный максимум gain=0 означает отсутствие более плотного плана.
После него остальные цели разрешают равенство заполнения.
Допустимый результат `Optimize.check()` сам по себе не является доказательством:
нижняя и верхняя оценки всех целей должны быть конечными целыми числами,
совпадать друг с другом **и с оценкой извлечённого плана**.

Все переменные дискретны и ограничены. Число разных достижимых дробей конечно;
при обновлении основной цели дробь строго улучшается.
Отдельные проходы поддержки тоже конечны и добавляют только новые ограничения.

## Границы и сокращение поиска

Проверенный начальный план задаёт включающую равенство границу качества.
Для сравнения заполнения применяется точное перекрёстное умножение.
При равном заполнении граница учитывает количество, объём товаров и число коробок.

Используются следующие безопасные ограничения:

- U <= V, заполнение не выше 100%.
- Число коробок не меньше U/max_box_volume и packed_weight/max_box_weight.
- V не меньше packed_weight, умноженного на минимальное отношение
  box_volume/max_weight среди подходящих типов.
- При r=p/q>0: V <= floor(order_volume*q/p). Здесь order_volume включает весь
  заказ, поэтому ограничение безопасно и для частичного начального плана.
- Тип коробки с объёмом выше этой границы исключается; число слотов ограничивается
  floor(max_V/min_box_volume), остатками и количеством предметов.
- Из U<=V следует нижняя оценка минимизируемой цели:
  -gain >= -(q-p)*order_volume. При r=1 положительный gain сразу исключён.
- Фиксировать обязательную упаковку всех единиц можно только если начальный план
  уже упаковал весь заказ **со 100% заполнением**. Полный план с меньшим процентом
  не даёт такого права.

Совместимость учитывает разрешённые ориентации, размеры и вес.
Пары, которые не могут одновременно поместиться ни в один тип коробки
по объёму, весу или разделяющей геометрической оси, разводятся по разным слотам.
Остатки не разворачиваются в тысячи экземпляров: не более N слотов на весь заказ.

Слоты нумеруются по первому назначенному предмету, одинаковые единицы товара
упорядочиваются по слоту и координатам. Это устраняет равнозначные перестановки.
Начальные координаты передаются как подсказки, без фиксации геометрии.

## Опора и независимая проверка

Предметы находятся внутри коробки, не пересекаются и соблюдают суммарный вес.
Касание разрешено. Предмет стоит на дне либо **100% основания** покрыто верхними
гранями предыдущих предметов. Допустима совместная опора нескольких товаров.
Стандартная эвристика использует порог 80%, резерв Z3 — 100%.

В начальной модели есть необходимое условие контакта с опорой.
Точный геометрический проход обнаруживает зазоры в объединении верхних граней,
после чего добавляет символические контрольные точки. Ограничения добавляются
после выхода из check(), вне callback. Миллиметровая сетка не строится.
Доказанный оптимум ослабленной модели, прошедший полный валидатор, оптимален
и для исходной задачи. Количество контрольных точек конечно, в худшем случае O(N³).

## Агрегатный сертификат

Перед геометрическим поиском небольшая модель проверяет, возможен ли вообще
строго лучший результат по всем четырём целям. Она учитывает количество товаров,
остатки, объём, вес, совместимость и консервативные парные оценки.

Количество каждого товара **разделено по ориентациям**.
Фиксированные оценки вместимости по трём осям применяются только к одной
конкретной ориентации. Нельзя применять их к сумме `LWH` и `WLH`:
смешанная укладка «вертушкой» может вместить больше, чем любая однородная сетка.
Для товара без наклона дополнительно допустима оценка
floor(box_height/item_height)*floor(box_base_area/item_base_area).

Только UNSAT выдаёт сертификат. SAT или UNKNOWN передают задачу геометрическому
решателю. Сертификат допустим и для частичного заказа, если лучшее заполнение
и последующие цели доказаны. Проверка ограничена 50 000 единиц работы Z3.
При более чем 12 товарах или 64 типах коробок этот ускоритель пропускается;
большие каталоги не обрезаются. Парные ограничения добавляются при не более
24 вариантах ориентаций; их пропуск только ослабляет оценку.

## Конечный бюджет, процессы и отмена

На каждый геометрический процесс выделено **50 000 000 единиц работы Z3**
(`SOLVER_RESOURCE_LIMIT` в `z3_model.py`).
Из бюджета вычитается накопленный `rlimit count` контекста: повторы ради нового
заполнения, чужой границы или опоры его не обнуляют.
При исчерпании возвращается лучший проверенный план с `reason=resource_limit`.
Он имеет статус `feasible` либо `fallback`, оптимальность не заявляется.

Это ограничение работы решателя, а не гарантия длительности всего HTTP-запроса:
эвристическая подготовка и построение модели зависят от размера заказа.
Старое `solver_timeout_ms` по-прежнему принимается для совместимости и игнорируется;
`time_limit_ms=null`. Все этапы остаются отменяемыми.
Отмена останавливает процессы без выдачи результата как завершённого расчёта.

`solver_workers` по умолчанию 4, фактически не больше доступных CPU.
Процессы запускаются через multiprocessing spawn, имеют отдельные контексты Z3
и передают проверенные улучшения через ограниченные неблокирующие очереди.
При доказательстве, завершении или отмене весь портфель освобождается.
Значение `progress=null` означает, что доля выполненного доказательства неизвестна.

После поиска укладка внутри каждой коробки может быть уплотнена с сохранением
назначенных товаров и полной опоры. Эта стадия не меняет заполнение.

## Результат и проверка

`status=success/partial/impossible` описывает полноту заказа.
`optimization.status=optimal` означает доказательство описанных целей;
`feasible` — проверенный план без доказательства; `fallback` — эвристический резерв.
Причины: `completed`, `resource_limit`, `solver_error`; прежние
`time_limit` и `size_limit` поддерживаются при чтении старых результатов.

Версия pipeline: `z3-packing-v1`. Выбор: `options.algorithm="z3"`.
REST, PostgreSQL, placements, 3D и генератор инструкций общие для алгоритмов.
Центр масс, прочность упаковки и траектория загрузки не моделируются.

Регрессии: `test_fill_bounds.py`, `test_z3_refinement.py`,
`test_z3_certificate.py`, `test_z3_engine.py`.
Малые задачи сравниваются с независимым перебором всех возможных суммарных
объёмов коробок; при каждом фиксированном объёме отдельно оптимизируется U.

```sh
cd backend
uv run pytest -m "not stress"
```

Семантика оценок решателя: [официальный API Z3 Optimize](https://z3prover.github.io/api/html/classz3py_1_1_optimize.html).
