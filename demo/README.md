# Демонстрационные сценарии

Это фиксированные примеры контракта для разработки API и интерфейса. Координаты,
коробки и ориентации заданы вручную; поиск размещений и оптимизация здесь отсутствуют.
Каждый ответ явно содержит `DEMO_STUB` и `algorithm_version: "demo-stub-v1"`.
Проверки подтверждают согласованность снимков, но не качество будущего алгоритма.

| ID | Сценарий | Статус | Коробки / товары |
|---|---|---|---|
| `simple-order` | Две упаковки чая | `success` | 1 коробка S / 2 из 2 |
| `multiple-boxes` | Чайники, фильтры и термосы | `success` | 2 коробки M / 6 из 6 |
| `oversized` | Длинный тубус для постера | `impossible` | 0 коробок / 0 из 1 |
| `stock-shortage` | Подарочные наборы при дефиците коробок | `partial` | 1 коробка S / 1 из 3 |

`scenarios.json` — массив `{id,name,description,expected_status}` для выбора сценария.
Каждому ID соответствуют полные `<id>.request.json` и `<id>.response.json`.
`catalog.boxes.json` — массив `BoxType[]`, отсортированный по ID, для первичного
заполнения PostgreSQL. Остатки в запросах — отдельные снимки; расчёт их не списывает.
Сценарий дефицита намеренно содержит подходящий тип коробки с нулевым остатком.

Размеры и координаты в мм, масса в граммах. Все размещения опираются на дно коробки.
В сценарии нескольких коробок фильтры повёрнуты `WLH`; у чайников и термосов
повороты запрещены. Инструкции включают подготовку коробки, каждый шаг размещения
и закрытие; на каждом шаге координаты и размеры совпадают с `placements`.
Список альтернатив пока пуст: сравнительные планы создаст Packing Engine Engineer.

Stub возвращает снимки для совпадающих `boxes` и `products`, независимо от порядка
строк. Другой валидный заказ получает HTTP 503 `ENGINE_NOT_IMPLEMENTED`.
После подключения движка ожидаются реальные расчёты; эти снимки остаются примерами
геометрически корректных ответов, а не обязательными точными результатами эвристики.

При изменении вручную заданных сценариев можно пересобрать JSON:

```sh
python demo/generate_fixtures.py
cd backend
python -m pytest tests/test_demo_fixtures.py
```

Скрипт запускается только разработчиком и не участвует в обработке HTTP-запросов.
Текст инструкций берётся из общего `app.services.instructions.build_instructions`,
поэтому снимок ответа и ответ API используют один источник текста.
Канонический контракт: [docs/CONTRACTS.md](../docs/CONTRACTS.md).
